# CartService

เพิ่ม `CartServiceImp` ตาม interface เดิม และให้ `AuthService` เรียกสร้างตะกร้า
ผ่าน service นี้ตอนสมัครลูกค้า

ใช้ Repository สำหรับข้อมูลตะกร้าและการล็อกลูกค้า ส่วนการเพิ่มสินค้าเรียก
`ProductService.getProductById` ผ่าน interface ต้องมี implementation นี้ก่อนใช้งานจริง
ในเทสจำลอง ProductService โดยไม่ได้เขียน service สินค้าเพิ่ม

## การทำงาน

- `createCart` สร้างตะกร้าให้ลูกค้าที่มีอยู่ในระบบ ถ้ามีตะกร้าแล้วจะคืนอันเดิม
- `getCartByCustomerId` อ่านตะกร้าพร้อมรายการสินค้า ถ้าไม่พบจะโยน `NoSuchElementException`
  โดยไม่สร้างตะกร้าขึ้นมาเอง
- `addItemToCart` เพิ่มสินค้า ถ้ามีสินค้าเดียวกันอยู่แล้วจะรวมจำนวนในรายการเดิม
  และคงค่า `isSelected` เดิมไว้ รายการใหม่จะถูกเลือกไว้ก่อน
- `updateItemQuantity` เปลี่ยนเป็นจำนวนที่ส่งมา ไม่ใช่บวกเพิ่ม
- จำนวนต้องมากกว่า 0 ถ้าต้องการลบให้เรียก `removeItemFromCart`
- `removeItemFromCart` ลบได้เฉพาะรายการที่อยู่ในตะกร้าของ customerId ที่ส่งมา
- `clearCart` ลบสินค้าทั้งหมดในตะกร้านั้น รวมรายการที่ไม่ได้เลือก แต่เก็บตัวตะกร้าไว้

การเพิ่มและแก้จำนวนจะเช็กสต็อก สถานะสินค้า สถานะร้าน และสถานะบัญชีผู้ขาย
สินค้ากับร้านต้องเป็น `ACTIVE` และบัญชีผู้ขายต้องไม่ถูกระงับหรือปิดใช้งาน
ถ้าจำนวนไม่ถูกต้องหรือสินค้าไม่พร้อมขายจะโยน `IllegalArgumentException`

## เตรียมสั่งซื้อ

`validateCartStock` ตรวจเฉพาะรายการที่ `isSelected = true` ถ้าไม่มีรายการที่เลือก
หรือมีรายการที่ซื้อไม่ได้จะคืน `false`

`splitCartBySeller` แบ่งรายการที่เลือกตาม sellerId ถ้าไม่ได้เลือกสินค้า หรือมีสินค้า
ที่ซื้อไม่ได้จะโยน `IllegalArgumentException` ไม่คืนรายการบางส่วนให้ไปสั่งซื้อ

การใส่ตะกร้าไม่จองหรือตัดสต็อก ตอนสร้างคำสั่งซื้อจริงยังต้องตรวจและตัดสต็อก
ภายใน transaction ของการสั่งซื้ออีกครั้ง

## สิ่งที่ต้องรู้ก่อนต่อ API

- การแก้ตะกร้าจะล็อกแถวลูกค้าจนจบ transaction เพื่อไม่ให้คำขอที่เข้าพร้อมกัน
  สร้างตะกร้าซ้ำหรือเขียนจำนวนทับกัน
- customerId ต้องมาจากผู้ใช้ที่ยืนยันตัวตนแล้ว ห้ามเชื่อ customerId จาก request
  โดยไม่ตรวจเจ้าของ เพราะ service นี้ไม่ได้อ่าน token เอง
- CartController อ่าน customerId จาก token และส่งเฉพาะ response DTO
- ยังไม่มีคำสั่งเปลี่ยน `isSelected` ใน interface

## HTTP endpoints

ทุกเส้นทางต้องส่ง `Authorization: Bearer <token>` ของบัญชีลูกค้า ไม่รับ customerId
จาก request และไม่เปลี่ยนการตรวจสิทธิ์ของ Controller อื่น

| Method | Route | ข้อมูล |
| --- | --- | --- |
| POST | `/api/cart` | สร้างตะกร้าหรือคืนอันเดิม |
| GET | `/api/cart` | อ่านตะกร้าของผู้ใช้ |
| POST | `/api/cart/items` | body: productId, quantity |
| PATCH | `/api/cart/items/{itemId}` | body: quantity |
| DELETE | `/api/cart/items/{itemId}` | ลบรายการ ตอบ 204 |
| DELETE | `/api/cart/items` | ล้างตะกร้า ตอบ 204 |
| GET | `/api/cart/stock` | คืนค่า valid |
| GET | `/api/cart/sellers` | รายการที่เลือกแยกตาม sellerId |

Token ไม่ถูกต้องตอบ 401 บัญชีที่ไม่ใช่ลูกค้าตอบ 403 รายการที่ไม่อยู่ในตะกร้าตอบ 404
และจำนวนไม่ถูกต้องหรือสต็อกไม่พอตอบ 400

## ทดสอบและ commit

รัน `mvn test` ในโฟลเดอร์ backend ด้วย Java 25 การทดสอบตะกร้าใช้ H2 แยกจาก
ฐานข้อมูลจริง ครอบคลุมเพิ่ม แก้ ลบ สต็อก การแยกตามร้าน และคำขอที่เข้าพร้อมกัน
ยังไม่ได้ทดสอบกับ PostgreSQL จริง

เมื่อทดสอบผ่านให้ commit งานตะกร้าแยกจาก AuthService:

    feat(cart): เพิ่มการจัดการตะกร้าและตรวจสอบสต็อกสินค้า
